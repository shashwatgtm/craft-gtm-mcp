Who is Retention Playbook not ideal for?

  • Anyone who cannot give the required inputs (Customer segment, Business model, Current churn rate); the answer is built only from them.
  • Teams that want finished, publish-ready plans: each tool returns a structured draft, with placeholders where your inputs gave no fact.
  • Anyone who needs live market or competitor data: the tools look nothing up; they work from what you type, and anything they add themselves is marked as an example, a suggestion or a placeholder.

How do I use Retention Playbook from Claude?

Connect CRAFT GTM once (see Connect), then ask in plain words. A prompt built from the tested example:

Use CRAFT GTM's Retention Playbook tool. customer segment: SMB accounts; business model: saas subscription; current churn rate: 4% monthly; churn reasons: onboarding friction, missing integrations; cs team size: small 1 3.

MCP tool name: retention_playbook. REST: POST https://craft-gtm.gtmhelix.com/api/tools/retention_playbook with this JSON body (see Docs):

{
  "input": {
    "customer_segment": "SMB accounts",
    "business_model": "saas_subscription",
    "current_churn_rate": "4% monthly",
    "churn_reasons": "onboarding friction, missing integrations",
    "cs_team_size": "small_1_3"
  }
}

How does Retention Playbook work?

It applies fixed rules in the CRAFT GTM code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server call the same tool code, so the same input gives the same answer in both.
