Who is CRAFT GTM Analyzer not ideal for?

  • Anyone who cannot give the required inputs (Document content, Document type); the answer is built only from them.
  • Teams that want finished, publish-ready plans: each tool returns a structured draft, with placeholders where your inputs gave no fact.
  • Anyone who needs live market or competitor data: the tools look nothing up; they work from what you type, and anything they add themselves is marked as an example, a suggestion or a placeholder.

How do I use CRAFT GTM Analyzer from Claude?

Connect CRAFT GTM once (see Connect), then ask in plain words. A prompt built from the tested example:

Use CRAFT GTM's CRAFT GTM Analyzer tool. document content: Q1 plan: grow pipeline 30% by launching two webinars and an outbound sequence to mid-market finance leaders. Owner: marketing lead. Budget: ...; document type: quarterly plan.

MCP tool name: craft_gtm_analyzer. REST: POST https://craft-gtm.gtmhelix.com/api/tools/craft_gtm_analyzer with this JSON body (see Docs):

{
  "input": {
    "document_content": "Q1 plan: grow pipeline 30% by launching two webinars and an outbound sequence to mid-market finance leaders. Owner: marketing lead. Budget: $20K. Success metric: 40 qualified opportunities.",
    "document_type": "quarterly_plan"
  }
}

How does CRAFT GTM Analyzer work?

It applies fixed rules in the CRAFT GTM code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server call the same tool code, so the same input gives the same answer in both.
